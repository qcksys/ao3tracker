# Native offline reading plan

The native app should let readers continue through downloaded AO3 chapters in the existing Read tab, using their selected AO3 site skin. Losing internet, restarting the app, or changing chapters must preserve the reading experience and local progress.

The Android implementation and verification are complete in this checkout. Manual downloads, automatic caching, storage controls, and saved chapter reading use the existing interface. The confirmed priorities are native first, the same reading interface online and offline, and site skins ahead of author work skins. The user narrowed the first release to Android on 2026-10-03 and selected default/Reversi plus custom inherited/replacement fixtures for compatibility checks. iOS, the browser extension, and the desktop reader are follow-ups; the desktop app currently has no embedded WebView.

## Recommended first release

- Download nothing by default. When the reader enables **Save chapters as I read**, save the current chapter after a successful load and prefetch a configurable number of upcoming published chapters (default two, zero for current-only, or all).
- Offer **Save whole work** in Read and Work Details. This saves the chapters published when the download starts; show new chapters as available to download later.
- Preserve the current AO3 site skin, including custom and inherited skins, across every downloaded work and offline restart.
- Open saved chapters immediately through the existing reader. Show **Saved copy** when connected and **Offline** when disconnected, with download coverage available from the same control.
- Keep progress local and sync it through the existing coordinator when a connection returns.
- Show **Available offline** in Works, plus a filter, per-work progress, retry, update, and remove actions.

Automatic saving, prefetch, and background refresh are off by default. Enabling **Save chapters as I read** opts into all three. The automatic-download allowance is 250 MiB, shared across local account partitions. Explicit downloads are outside that allowance and show their size separately. Prefetch uses Wi-Fi by default; explicitly requested downloads may use the current connection. Settings has a separate Offline reading accordion with automatic saving, custom/all prefetch, the Wi-Fi preference, opt-in deletion of completed automatic chapters, storage totals, and clearing of automatic saves across accounts. Save whole work downloads are always protected from automatic deletion. Open chapters retain their files until closed; reading progress is unchanged by deletion. Offline editing of AO3 comments, kudos, subscriptions, and searches is outside this release.

## Site skin preservation

AO3 can emit a skin through both linked CSS files and inline style elements. Its source handles ordered parent skins, skins that replace the default styling, and media rules for screen widths and light or dark mode. Capture the styles AO3 actually emits rather than trying to reconstruct a skin from its name. This is based on the upstream [skin model](https://github.com/otwcode/otwarchive/blob/master/app/models/skin.rb); verify its assumptions against current pages during the first implementation milestone.

### Capture a complete theme

Capture a theme from a successfully loaded foreground AO3 work page using the existing AO3 login session. Store an ordered manifest of stylesheet content, original resource URLs, media attributes, and enabled state. Include styles whose media conditions do not currently match. Preserve CSS rules instead of saving computed styles, so rotation and system appearance changes still work.

Resolve relative resource URLs against each stylesheet's original URL. Save required imports and referenced assets, rewriting them to local resources. Retain the DOM IDs, classes, wrappers, language, and viewport metadata needed for site styling. AO3's [application layout](https://github.com/otwcode/otwarchive/blob/master/app/views/layouts/application.html.erb) and [work view](https://github.com/otwcode/otwarchive/blob/master/app/views/works/show.html.erb) provide initial fixture structure, but authenticated and custom-skin page fixtures are still required.

Keep site styling separate from work-specific styling and app-injected tracking styles. Preserve their original cascade positions when composing a saved page. Do not unconditionally add default AO3 CSS to a replacement site skin.

The complete stylesheets are required before declaring site-skin preservation successful. Track missing images or fonts separately. A chapter can be readable with missing media, but the interface must disclose that and must not claim the appearance is fully saved. System fonts continue to depend on what is installed on the device.

### Select and refresh a theme

Maintain one active saved site-skin revision per local tracker account and AO3 browsing identity. Each chapter keeps a reference to its original successful revision as a fallback. A newly opened downloaded chapter uses the latest complete compatible active revision; a chapter already displayed keeps its selected revision until the next navigation or an explicit refresh.

Only a successful foreground page observation changes the selected skin. Background chapter downloads, login screens, error responses, skin previews, and unknown AO3 authentication state must not replace it. AO3's [skin selection helper](https://github.com/otwcode/otwarchive/blob/master/app/helpers/skins_helper.rb) distinguishes request, session, account-preference, and default selection; the app must distinguish a preview from a persistent selection during the feasibility work.

Hash stylesheet contents, their order, and their conditions to identify revisions. Do not rely solely on a skin ID, title, or CSS URL: a custom skin can change without changing those values. Fetch or conditionally revalidate linked styles when refreshing. Switch the active revision only after the complete bundle has been published; keep the last good revision on failure.

Changing the saved site skin updates the rendering of existing downloads without downloading chapter text again. An account change made on another device becomes visible after this app successfully loads a fresh AO3 page. The first release keeps the latest selected skin and fallback revisions; a picker for several offline skins is deferred.

Native app colours do not override the AO3 site skin. If the skin itself contains system light/dark rules, preserve their behaviour. Suppress progress reporting during initial styling and position restoration so a layout change cannot mark unread content as read.

Author work styles are captured separately when present. Advanced work-skin controls are secondary; they must not delay reliable site-skin support. Cached reading controls must remain usable even when site CSS hides or rearranges AO3 controls.

## Reader loading and navigation

Add an internal reader destination that distinguishes a live URL from a saved chapter. Both retain the canonical AO3 URL, work ID, chapter ID, requested fragment, and reading position. Keep local serving URLs out of copied links, sync payloads, and work identity.

| Situation                                     | Reader behaviour                                                                                                                         |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Complete saved chapter exists                 | Open it immediately; check for updates separately when connected.                                                                        |
| Chapter has no saved copy and AO3 responds    | Open the live page, validate it, and save it.                                                                                            |
| Connection fails while reading                | Leave the displayed chapter and position intact.                                                                                         |
| Next chapter is saved                         | Navigate locally using the same chapter controls.                                                                                        |
| Next chapter is missing offline               | Keep the current chapter available and show which chapters are saved. Do not advance completion merely because navigation was attempted. |
| Works resume points at an unavailable chapter | Explain the gap and offer the last saved chapter; do not silently change the requested destination.                                      |
| A refresh finds updated content               | Save a new revision; apply it on the next open or explicit refresh.                                                                      |

Normalize transport aliases and strip only app-owned progress/cache-busting parameters from cache identity. Preserve meaningful options such as chapter versus whole-work view. Use stable work/chapter IDs and an explicit representation key; fragments are navigation state. Handle chapter-zero replacement using the existing canonical chapter mapping rather than treating it as another work.

The implementation stores individual chapter pages. Whole-work navigation shows an explicit choice of available saved chapters or the online whole-work view, preserving the current page until a choice is made. A foreground whole-work capture can update the saved site skin; it does not save aggregate text as chapter one or advertise individual chapters as downloaded. Save whole work queues chapter discovery and individual downloads. Fragments remain part of navigation, and Try online retains the requested whole-work fragment. Back and forward history represent user navigation, not an extra step for every live-to-local fallback.

Room migration 11→12 adds each chapter's nullable download revision from the AO3 download URL's `updated_at` parameter. Older snapshots remain readable with an unknown revision. While automatic saving is enabled, newer captured or synced download timestamps queue stale copies of the current work for refresh, alongside the selected prefetch count. Opening a saved chapter at least 30 minutes old also queues a refresh to check for changes not yet observed. These jobs obey Wi-Fi, quota and cooldown policy. The displayed revision and position remain unchanged; the refreshed revision is used on the next open. Update saved work is available for an immediate explicit refresh, including when automatic saving is disabled. Download coverage also follows newer published-chapter counts received through library sync and offers Update saved work when the saved manifest is older.

Android downloads run in a `dataSync` foreground service with an ongoing progress notification and a bounded partial wake lock, following [Android foreground-service requirements](https://developer.android.com/develop/background-work/services/fgs/launch). The service owns its capture WebView, independent of the activity, and continues when switching apps or locking the screen. It starts while the app is visible and stops after the eligible queue completes, connectivity is lost, or Android applies its [service timeout](https://developer.android.com/develop/background-work/services/fgs/timeout). Interrupted chapters remain queued for reopening the app; a force-stopped process is not restarted automatically.

Tap download progress to open the same style of debug dialog as sync, including queue state, failed attempts, retry/cooldown times, saved download revisions and the latest 100 local steps. Capture failures report sanitized phase, exception type and safe error category through PostHog when diagnostics are enabled and incognito is off. Raw error messages from page scripts are allowlisted before display or reporting; content, URLs, account identity and cookies are excluded.

Use a native download/status control outside the AO3 document so a custom skin cannot hide availability or retry actions. Offline AO3 server actions show that a connection is required; they are not queued. Saving a work is distinct from reading it.

## Storage and module responsibilities

Keep a small content module responsible for resolving reader destinations, scheduling saves, observing availability, refreshing, and removing downloads. Keep Android resource loading and AO3-session fetching behind platform adapters that can later support iOS. Screens should not implement file paths, cache policy, or account checks independently.

| Stored record      | Purpose                                                                                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Work download      | Work ID, ordered chapter manifest, pin state, manifest observation time, and aggregate coverage.                                                      |
| Chapter snapshot   | Chapter ID, representation, canonical URL, snapshot revision, schema version, saved time, file reference, fallback skin revision, and missing assets. |
| Site skin revision | Ordered stylesheet manifest, resource references, content hash, capture time, and AO3 context.                                                        |
| Resource           | Account-scoped content hash, media type, file reference, size, and optional HTTP validators.                                                          |
| Download job       | Owner/context generation, target, queue state, completed chapters, retry time, and bounded error category.                                            |

Use the existing Room version and migration approach for indexes and durable jobs. Store HTML, CSS, and media in app-private persistent storage, outside OS-evictable cache directories and excluded from cloud backup. Files and theme revisions are device-local and excluded from API sync, guest imports, and metadata exports. No server API changes are expected.

Stage files under generated names, verify completeness and hashes, then commit their references in a Room transaction. Filesystem operations and database commits are not one atomic transaction: publish files before references, retain old references until success, and collect orphan staging files after restart. A corrupt or missing file becomes unavailable rather than causing an endless reload. Shared assets remain while any snapshot, active theme, fallback theme, or open reader references them.

Use least-recently-used eviction only for automatic saves. Protect the open chapter, the currently promised upcoming chapters, explicit downloads, and their theme/resources. If protected content fills the allowance, pause new automatic downloads. Explicit downloads stop with an actionable space warning when storage is insufficient; never remove pinned works to make room.

## Download execution and AO3 access

Use the AO3 WebView cookie session for content access, independently of tracker API authentication. Reuse the separate-WebView approach already used for search checks, with a capture-only script and no reading tracker. The Android foreground service owns its lifecycle independently of tabs and the activity. OS termination can still interrupt it; durable jobs resume when the app reopens.

Run one download at a time. Interactive reading takes priority. Respect Retry-After on throttling responses, retain a shared AO3 cooldown with search checks, and back off after failures. Capture size and asset-count limits during the feasibility work so malformed or very large pages cannot exhaust memory. Transfer large HTML in bounded chunks or through a platform file path rather than one unbounded bridge message.

Validate a real work/chapter document and its identity before saving. HTTP success alone is insufficient: login, adult-warning, unrevealed-work, deleted-work, and rate-limit pages must never replace story content. Background fetching must not accept an adult warning on the user's behalf; resume after they open the work and make the required choice. A failed access check preserves the last saved copy with a clear status.

An explicit whole-work job freezes a published-chapter manifest for consistent coverage and can be resumed chapter by chapter. Updating a saved work refreshes that manifest and checks existing chapters for edits, including changes without a chapter-count increase. Do not erase the previous revision on a failed update. Preserve downloaded text after remote edits/deletion until the reader removes it; label it as a saved copy and never restore a remotely deleted library row merely by rendering it.

## Accounts and local page trust

The tracker account and AO3 account are separate identities. Bind jobs, skin selection, and snapshots to the tracker owner/environment plus an opaque local AO3 context. Establish that context from observed logged-in identity or a confirmed logged-out page; retain it across offline restarts. Do not store cookie values in manifests or assume a network failure means logout. The first milestone must prove reliable identity and skin-selection observation; an ambiguous context pauses capture and keeps the last good selection.

On a tracker or confirmed AO3 identity change, cancel old jobs, clear the rendered page/history, and reject late messages and commits from the previous generation. Previously stored data stays in its own context until explicitly removed and is never served under the replacement context. An offline startup restores the last locally selected account/context without waiting for a successful API session request; sync still requires the existing verified-session checks.

Extend explicit clear-data and successful sync-and-sign-out cleanup to remove that owner's download indexes, theme selection, and files. Removal of a download alone must not remove progress. Cancelled or failed sign-out sync must preserve downloads and pending reading edits. Keep file cleanup scoped and restart-safe so it cannot delete a replacement account's files.

Serve local content through a dedicated origin using Android's [WebViewAssetLoader](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content). Validate the local resource loader and bridge on Android before committing to the serving format. iOS's [WKURLSchemeHandler](https://developer.apple.com/documentation/webkit/wkurlschemehandler) is a candidate for the later iOS implementation. Do not widen the existing trusted-AO3 URL predicate to arbitrary local files or origins.

Only app-authored reader JavaScript executes in saved documents. Remove scripts, inline event handlers, tokens, executable URLs, embeds, and form submissions while retaining styling hooks. Block unexpected network requests in local documents. Native code must validate the active document token, main-frame/source context where available, account generation, and manifest identity before accepting progress or navigation. It derives the canonical URL from that context, not from a message claiming an AO3 URL. Asset fetches must not forward AO3 cookies to external hosts or after cross-origin redirects.

Incognito stops automatic capture, prefetch, progress writes, and diagnostics. Existing downloads remain readable. An explicit Save action can still persist content, labelled as such; queued automatic jobs cannot complete after incognito starts. Downloaded text, CSS, URLs, and private skin contents never enter diagnostics.

## Reading progress

Route offline reading events through the existing repository and sync coordinator. Keep existing last-read clocks, completion behaviour, mark-unread handling, and chapter tombstones. Add a debounced reconnect/foreground sync request; connectivity signals are hints and successful requests remain authoritative.

Offline rendering must not replay saved work metadata through the live ingestion path. Split reading-session initialization from live metadata ingestion so a saved page can establish the current chapter without overwriting newer title, tags, chapter counts, privacy, or deletion state. Prefetch and validation emit no reading events. A deleted library entry can be restored only through an explicit action.

Restore position after local styles and layout are ready, then enable progress reporting. Preserve the existing percentage semantics for sync. If theme changes require a more stable resume location, store an element anchor and offset locally alongside the existing percentage, with percentage fallback when the chapter text changes; evaluate this in the rendering milestone before adding another cross-device field.

## Verified decisions and deferred scope

Capture and Android fixtures establish separation of site/work styles, rejection of previews and ambiguous identities, inherited/replacement skin order, and the isolated local origin and bridge. Captures are bounded to 1,000 assets, 16 MiB per resource, 64 MiB per bundle, and 8 MiB of source HTML, with chunked transfer. Percentage restoration passes the Android rotation, appearance, and cold-start checks; an additional cross-device anchor field is unnecessary for this release.

The 250 MiB allowance, Wi-Fi default, and missing-media labels can be adjusted without changing the storage design. Downloads continue across app backgrounding and screen lock, but process termination requires reopening the app to resume. A multi-skin offline picker, full offline AO3 browsing, and iOS/extension/desktop support are deferred.
